# 输入侧(上游层)span 可卸载性指标:定义、实验证明与解释

**状态**:2026-09-20,合并数据集 96 个配对 span 验证(旧 screening 101 span,engine 2026-09-12.3 + batch1 最新 49 span,engine 2026-09-20.2,零重叠合并后 150 span,其中三臂各 ≥3 轮的 96 个进入配对分析)。

**口径**:
- 结果变量:`T_strict` = T 臂(SLM 卸载)轮内 strict 成功率;`T−B` = 与 baseline 重采样臂之差(干预净效应);`T−I` = 与 identity 注入臂之差;
- 400 协议失败按"如实失败"计(strict=False);
- 所有指标在**卸载决策之前**可计算,只使用:本次 span 请求的**前缀会话窗口**(`downstream_trace.prefix.messages` + `prefix.previous_tool_results`)——即"上游"信息,不碰下游、不碰 trace 事后分类标签、不碰基线输出;
- 分层方法:连续指标三分层(tercile),自然分组指标直接分组;每组报 n / T / eq / T−B / T−I。

---

## 指标 L1:进展度(Progress)

**具体含义**:前缀会话的"长度"——上游已经走了多远。三个共线度量(取一即可):

| 度量 | 计算方式 |
|---|---|
| `prompt_msgs` | `prefix.messages` 的消息条数(system/user/assistant/tool 全算) |
| `n_tc` | 前缀消息里全部 `tool_calls` 的个数 |
| `apps` | 前缀工具名的 app 前缀去重数(如 `phone__search_contacts` → `phone`) |

**实验数据**(合并 96 span):

| 分层 | prompt_msgs | n_tc | apps |
|---|---|---|---|
| 低 | n=45,**T=0.43**(eq=0.24,T−B=−0.04) | n=45,**0.43** | n=45,**0.43** |
| 中 | n=24,0.50(T−B=−0.13) | n=22,0.55 | n=51,**0.68** |
| 高 | n=27,**T=0.83**(T−B=+0.02) | n=29,**0.78** | — |

**解释**:进展度是"决策依据可复制性"的代理。上游积累的工具调用与结果越多,当前 span 的输入上下文越具体,SLM 复现基线决策所需的信息越充分;开局 span 的上下文几乎只有任务指令,SLM 在信息最少处做首步决策,失败率最高。三个度量共线(同一批 span 的开局/中局/后局),报告中取 `prompt_msgs` 最稳。

---

## 指标 L4b:首次工具调用位点(硬拒绝)

**具体含义**:前缀里**没有任何工具调用**(`n_tc == 0`),且 assistant 教程回复 **> 6 条**。即:任务开始前有一段很长的纯对话教程(模型来回说了 12 轮左右的话、每条 5 字符上下的短应答),但还没有执行过任何工具——当前 span 是**任务第一次真正动手调工具**的位置。

**计算**:
```python
n_tc = sum(len(m.get("tool_calls") or []) for m in prefix_messages)
n_assist = sum(1 for m in prefix_messages if m.get("role") == "assistant")
L4b = (n_tc == 0) and (n_assist > 6)
```

**实验数据**:

| 来源 | n | T_strict | B_strict 范围 |
|---|---|---|---|
| 旧批(engine .12.3) | 11 | **0.00(11/11 全败)** | 0.00–1.00(1 个 1.00,其余 0.00) |
| 新批(engine .2) | 8 | **0.00(8/8 全败)** | 0.00–0.80 |
| 合计 | **19** | **0.00(19/19 全败)** | — |

对照组(同为零工具调用、教程 ≤6 条的 L4a):T=0.74。

**解释**:长教程 = 任务形态复杂(教学示范都要讲十几轮)或任务指令信息量大;此位点的工具参数选择完全依赖对整段任务描述的理解,**没有任何执行反馈可参照**。SLM 在"零执行参照 + 复杂任务理解"双重难度下 100% 失败;baseline 同一批 span 却有成功(0.80、1.00),说明不是任务无解,而是模型能力差距。**该信号跨两个引擎版本稳定成立,与装置实现无关**——这是当前最强的硬拒绝信号。

---

## 指标 L4a:预测位点(可卸载)

**具体含义**:前缀零工具调用(`n_tc == 0`),但教程回复 **≤ 6 条**——短教程之后的预测位点(输出任务所需 API 名单的模板化任务)。

**计算**:
```python
L4a = (n_tc == 0) and (n_assist <= 6)
```

**实验数据**:n=26,**T=0.74**(eq=0.42),**T−B=+0.01,T−I=+0.02**(与 identity 注入基线持平)。

**解释**:短教程预测位点是模板化输出(API 名单),输出结构固定、可 schema 校验;SLM 与 baseline 在此类位点几乎无差,且 identity 注入也不比 SLM 强——说明该位点**没有"复现基线"的必要性**,SLM 直接生成即可。可卸载的理想位点。

---

## 指标 L3:收敛信号(可卸载候选)

**具体含义**:前缀工具调用序列**最后 6 次**中,重复工具名的占比。0 = 近 6 次全用不同工具(探索期);1 = 近 6 次全是同一工具(收敛/局部迭代期)。

**计算**:
```python
last6 = tool_name_seq[-6:]
rep_last6 = sum(v - 1 for v in Counter(last6).values() if v > 1) / len(last6)
```

**实验数据**(富上下文内,即 prompt_msgs > 中位数的 44 span):

| 分组 | n | T_strict | eq | T−B | T−I |
|---|---|---|---|---|---|
| 低重复(探索) | 18 | 0.73 | 0.51 | −0.11 | −0.22 |
| 中重复 | 18 | **0.86** | 0.44 | −0.14 | −0.08 |
| 高重复(收敛) | 8 | 0.75 | 0.50 | **+0.25** | −0.12 |

**解释**:收敛阶段动作模式已经稳定,当前 span 大概率是"同一工具换个参数再试"的局部修正——这正是 SLM 擅长的浅层局部任务(与下游层发现一致:SLM 的错误是浅层局部错误,失败链短、一步重试即恢复;baseline 在收敛期仍可能发生深层分叉如空回复)。因此高重复组是**唯一 T−B 转正的组(+0.25)**:SLM 在此类位点不仅不输,反而优于 baseline 重采样。探索期每步都是新决策、状态独特,SLM 复制难(T−B −0.11)。低/中重复组的 T−I 为负(−0.22/−0.08)说明即便不算 B,相对 identity 仍有损失。

## 降级 / 剔除的指标(数据理由)

| 指标 | 结论 | 理由 |
|---|---|---|
| L2 历史参数平均长度(侦察 vs 执行) | **降级为观察项** | 最新数据判别力消退:富上下文内 0.74 / 0.83 / 0.79,无单调;仅 T−I=−0.21 提示短参数组可能偏弱 |
| narr_len 上游叙述量 | **并入 L4(早期误读已修正)** | 数据中不存在"有工具调用但零叙述"形态;"低叙述组"实为教程回复形态,已用 n_tc/n_assist 精确刻画 |
| last_res_len 上一步结果长度 | 剔除 | 整体分层与富上下文内分层方向反转(U 形不稳定) |
| fails_hist / last_failed 上游失败史 | 剔除 | 两批数据均无方差(前缀从未以失败结尾) |
| hist_tools / switches 工具多样性 | 剔除 | 与 L1 共线,交叉后无独立增量 |
| task_len / n_user 任务指令长度/外部轮次 | 剔除 | 判别弱或样本不足(n=3) |

## 路由决策表

| 情形 | 判据 | 动作 |
|---|---|---|
| 零执行 + 长教程(>6 回复) | L4b | **硬拒绝** |
| 零执行 + 短教程(≤6 回复) | L4a | **可卸载**(T≈identity) |
| 有执行记录 + 低进展(prompt_msgs 低分位) | L1 | **拒绝** |
| 有执行记录 + 富上下文 + 高重复率 | L3 | **可卸载候选**(T−B +0.25) |
| 其余 | — | 按成本权衡 |
